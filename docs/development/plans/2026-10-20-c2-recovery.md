用户批准：新增持久化恢复状态，同一 execution 最多三次自动恢复，耗尽保留上下文暂停；真实 MySQL 矩阵和原有回归，保留 T/J/D、原始 ACK、六字段全量对账及旧 C2 失败证据；不提交推送。

## 约束

- 当前未提交的运行计划边界改动保留；基线另存 `/tmp/pekko-c2-20261020/before`。
- 完整组模式才开启恢复，保留 execution/revision/connector/generation/lineage；从 D 起读，不覆盖 D。
- Sink 只分类与账本仲裁，Engine 关闭会话，Actor 决策和持久化有界恢复。
- 保留 T → J → 原始回调前缀 ACK、完整组身份和目标事务原子性。
- 三次累计预算不因 J 增长或进程重启清零，退避 1/2/4 秒。测试可缩短时间但不提高额度。
- 不恢复历史已终态的失败，不实现 DDL、多 owner、共享读取或查询投影。

## 步骤和验收

1. 新增 Actor 固定窗口测试，证明当前 C2 失败终态；增加安全失败描述、提交边界与组账本主键校验测试。
2. 实现 Sink 提交阶段分类、Engine 分类/释放信息传递；不能由清理错误覆盖提交未知。
3. 新增 Scheduled/AttemptStarted/Blocked 持久化事件和可选状态；Actor 的 timer、Engine 结果及内部进度回调按运行尝试隔离；查询在等待/暂停时仍可读。
4. 旧快照默认值、CBOR、预算/定时器/启动前后崩溃、迟到回调与释放失败均做局部测试。
5. 扩展真实 MySQL 代理/进程设施，运行 C2 A-F、R1-R7（含旧目标事务锁的提交/回滚两支），以及原有七窗口与两取消场景；不伪造源记录/确认。
6. 全后端与打包，独立审查；独立校验原始事件、账本/审计及六字段对账。新报告保存新结果，所有旧实验哈希不变。

## 改动归属

- engine：安全失败描述、可恢复性资格、阶段包装、实际释放结果。
- sinks：仅提交边界分类、事务前暂时错误、组账本 PK 检查；无内部重试。
- actors/events：恢复事件/状态、预算和退避、attempt 消息隔离。
- reference config、HTTP summary/status：默认参数和最少真实恢复诊断字段。
- test/integration：测试探针与协议代理；单独实验目录记录结果，不改旧材料。

## 核心验收

自动恢复案例必须同 execution 自动收敛：缺行/多行/字段差异均 0，业务审计与源序一致，ACK 为合法前缀，旧本地 Reader 退出后才创建替代 Reader。负例只验收安全暂停和上下文保留，不能计为恢复成功。
