# 源侧版本与跨事务续扫探针

状态：**MySQL 组件实验通过；不是已完成的恢复协议。** 在隔离 MySQL 9.5.0 的测试表中，INSERT 触发器在同一事务递增版本行。测试在真实 JDBC 连接上固定快照、回滚与迟提交时序；[结果](result.json)、[运行日志](runner.log)、[源码摘要](probe.sha256)、[实例与清理记录](environment-and-cleanup.json)。

- REPEATABLE READ 事务读取版本 2、第一页 `b`；另一连接提交更早的 `a` 后，旧快照仍看到版本 2，新连接看到版本 3，从 `b` 续读仍只得到 `d`。因此在该场景中新旧版本不一致可以提示放弃续扫。
- 未提交插入被回滚后版本保持 3。另一笔插入尚未提交时，检查连接也看到版本 3；它之后提交，版本才变为 4。版本检查当下的相等不能单独排除后续迟提交。

这些是 MySQL 实际事务观察，不包含 Debezium Reader、Actor Journal、Sink、恢复许可或生产协议。实验只覆盖 INSERT 触发器，未覆盖 UPDATE、DELETE、权限绕过、DDL、数据库恢复或版本溢出；也未证明检查与发放许可之间没有竞态。旧 owner 隔离、旧事务排空和可验证的最终授权边界仍是必要的后续工作。
