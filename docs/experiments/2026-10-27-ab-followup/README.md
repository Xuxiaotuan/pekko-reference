## 本轮观测

| 场景 | 实际结果 | 证据边界 |
|---|---|---|
| 静默首次启动，heartbeat 0 与 1000ms | 两例均观察到本 attempt ACK 和完成态 D，随后进入 `ADMISSION_READY` | 关闭 heartbeat 不必然不就绪；没有构造“缺少 ACK 或 D”的 A01 负例，也不能证明所有 skip 分支 |
| A03 实际 D 行锁与 snapshot 完成 | 固定真实 MySQL D 为 INITIAL，观察到 snapshot COMPLETED 和当前原始 ACK 已返回，新增请求仍被拒绝；释放 D 锁、实际 D 前进后才进入 ready | 真实 Reader 和状态库；没有在该样本中运行 Actor/Sink 恢复 |
| A04 无旧 B 的 Schema 中断 | 旧 JVM 在 Schema 窗口退出时源控制行为空；新版 JVM 重新选点、绑定第一个 B 并由 Actor/Sink 应用源更新，独立复算 4 行、24 字段相等，T 1 条、J 4 条 | 真实跨 JVM、MySQL Journal/Sink；目标初始数据是预复制基线，不能称在线全量初始化。第一次探针因测试 worker 缺少准入查询命令失败，原日志保留 |
| heartbeat 1000ms，已知基线 Actor/Sink 见证 | 一次源更新后完整源/目标各 4 行、24 字段相等，T 有 1 条、J 有 4 条；独立复算无差异 | 基线预复制，不是 LOW/HIGH 初始化或故障恢复验收 |
| R01 共享 Reader 七表回归 | 七表各 4 行，合计 28 行、168 字段相等；T 有 8 条，J 有 29 条 | 预复制基线上动态选择和持续捕获；不是七表在线全量初始化，也不是 70 万表规模验证 |
| 旧 PREPARED/INITIAL 和 B_BOUND/INITIAL | 均在新版创建 Engine 前 `SAFE_PAUSED`；B_BOUND 样本的源/目标历史差异保留 | 安全暂停不等于补回历史漏数；旧 JVM 与新版分别使用各自冻结版本 |
| A07 已提交但未绑定 B，加 INITIAL D | 旧 JVM 固定源控制行已提交、订阅 B_PENDING 且 D=INITIAL 后退出；新版返回 `UNBOUND_MARKER_UNPROVEN`，Engine 创建次数 0，保留原状态 | 真实旧新版及 MySQL；T/J 为空，这是安全暂停，不是目标恢复收敛 |
| A11 实际 D 语法损坏及 partition 错误 | 在独占 fixture 内分别注入，两支均返回 `CHECKPOINT_INVALID`、Engine 创建次数 0；损坏值及原值有记录，随后恢复原值并检查原状态 | 真实旧 B 状态上的两类注入；不覆盖全部 namespace 冲突形式 |
| 源 marker 已提交，COMMIT 回复丢失 | `MARKER_COMMIT_UNKNOWN`，控制行仍为 1 条，拒绝重复写入；样本源/目标各 4 行、24 字段相等 | 目标为预复制基线、T/J 为空，不能称目标恢复成功；释放仍标记未知 |
| R03 迟提交／迟回滚 | 两支均按实际事实进入安全暂停 | 不自动收敛；不能推断所有源事务故障窗口 |
| R06、R09、R10-mid | 固定 B 绑定、D 滞后、主键变更跨原始 ACK 的恢复测试通过；目标表各 4 行、24 字段经独立复算相等 | 测试使用已知基线；不声称覆盖 A10 全部 ACK/D 联合门 |
| R15 取消与重订阅 | 已取消的旧订阅不再接收后续源写；按预期源/旧目标出现差异 | 这是停止后的预期差异，不是对账相等，也不是 A14 的全部竞争分支 |
| A14 取消先于晚到绑定／绑定先于取消 | 固定 marker 行 callback 已返回、事务 END 未处理时取消，之后的绑定没有复活该代，订阅无 B；已绑定 B 的待定取消被拒绝，随后原代通过 K 停止。两支中另一表各 4 行、24 字段相等，均有实际 T/J | 源 COMMIT 结果未知时取消仍未验证；断言基于真实订阅与屏障记录。当前代码即使 `bind` 因 CANCELED 没有写 B，仍可能发送名为 `B_BOUND` 的观察事件，不能单凭该事件名证明持久绑定；本轮未修改生产事件语义 |
| R16 history、L、谱系、订阅记录、D/source 缺失 | 各自运行的固定注入进入安全暂停；R07 未绑定窗口也暂停 | 不能推广为所有损坏格式、所有控制行缺失或全部 A11/A12 分支 |
| A12 控制行缺失、ACK 帧缺失 | 独占 fixture 先保存目标行与 ACK 帧，再移除已绑定 B 的源控制行或一条 ACK；重启分别以 `CONTROL_ROW_MISSING_OR_CHANGED` 和 `CAPTURE_LOG_HEAD_INCONSISTENT` 拒绝 | 数据与 Actor/Sink 基线来自真实运行，但本次注入的验收是安全拒绝，不是恢复收敛；不覆盖所有 ACK 引用损坏方式 |
| 安静／忙源关闭和 L 事务未决 | 本地结束后服务端仍有会话或事务时 `UNKNOWN`，最终确认释放后可复用；L 未决时 owner 保留 | 真实资源释放证据；这些实验不含 Actor/Sink 逐字段恢复对账，也不构成释放时限 SLA |
| B04 真实 SDK callback 异常 | 测试在真实 callback 内注入异常，原异常保留；出错 callback 2 未被确认，ACK 已返回的只有 0、1；重复关闭返回同一操作，最终实例连接与事务为空 | 此样本未运行目标 Sink，源/目标按预期有 2 个字段差异，T/J 为空；资源观察器未配置时关闭结果为 UNKNOWN，不能据此声称任意场景均安全释放 |
| 观察器 B08 组件探针 | 新账号缺少 PROCESS 或源 UUID 不匹配时启动失败；运行中撤销 PROCESS 后已有活动连接仍为 `UNKNOWN`；切断观察器代理连接返回真实 JDBC `CommunicationsException`，独立捕获连接仍存活 | 真实 MySQL 上的组件探针，没有执行 Actor/Sink；未覆盖全部身份重建、事务归属与生产网络故障。断网探针证明观察失败，`UNKNOWN` 的转换另由纯模型测试覆盖 |
| 原有恢复窗口回归 | N0 为正常基线，J1/J2/C0/C1/K1/K2 命中相应固定故障；7 个场景各 64 行、384 字段经独立复算相等 | 原完整组恢复回归；不能替代尚未运行的 A/B 新切点或旧 C2 失败证据 |

## 需要继续验证与设计的边界

1. **A05 的可用性目标尚未满足。** 计划期望有可靠证据证明 `B_PENDING` 尚未调用源写时，恢复后使用同一身份首次写 B。当前 `CaptureStartupGuard` 对未绑定 marker 统一返回 `UNBOUND_MARKER_UNPROVEN`，并未持久化可用于证明此区别的启动证据。旧 PREPARE 探针直接登记后崩溃，当前版本安全暂停；它说明保守行为，不能声称实现了该分支的自动继续。仅看到控制表不存在行不能证明从未调用或不存在迟到提交。相同的保守分类也意味着 A09 不能仅凭完成态 D 宣称已具备未绑定 B 的自动恢复。
2. A01 的无证据负例和 snapshot/skip 完整交叉、A09 的 committed-unbound 与完成态 D 的精确坐标分支、A10 联合 ACK/D 锁门、A11 的其余 namespace 冲突、A12 其余 ACK 引用损坏形式、A13 并发同身份请求结合 Actor/Sink 的完整证据、A14 源 COMMIT 结果未知时取消、A16 旧 CBOR/完整态恢复，尚缺对应的固定切点或完整证据。A03 已固定 D 锁和 ACK 返回，但不代表 A10 中的双门故障恢复已覆盖。
3. B02/B03 的组件级有界等待已有纯模型结果，但仍缺所列完整 runner/executor 固定门；B04 仍缺带真实目标与 Journal 的关联窗口；B05、B06 的全部分支、B08 的服务器重启上下文和归属不明、B09 晚回复、B10 JVM 重启后的持久资源准入均未完成矩阵验收。现有本地/服务端采样不能代替这些测试。
4. 70 万真实源表、长期运行、生产 MySQL 故障、共享 Reader 自动接管和 Flink CDC 同负载比较均未由本轮验证。任何未保存端到端 T/J/D、原始 ACK 和逐字段行集的场景都不标成端到端收敛。
