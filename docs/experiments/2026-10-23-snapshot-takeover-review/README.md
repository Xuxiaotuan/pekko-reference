# 自动接管提交前审查：触发缓存与恢复边界

这是[初版自动接管实验](../2026-10-23-snapshot-takeover/README.md)之后的独立修复与复核。旧目录及其校验和保持原样，末段“缓存尚未修复”描述的是历史冻结源码；当前实现、执行命令和结果以本目录的清单为准。基线为 `7ec75d716779d760972ab76f925465dbf953e7c0`，运行时尚未提交，不能用基线 SHA 代表新增代码。最终提交见 Git 历史；每次实验的 source.zip、源码散列和冻结 JAR 单独保存。

## 修复依据与源码结论

`TableSchedulingRuntime.reject` 原先在拒绝失败任务后只清除 `owned`，遗漏 `scheduledTriggers`。新增行为测试在修复前实际失败：SQL 已释放而本地仍得到 `Some(SnapshotScheduledTrigger(...))`。保留原始 RED 日志，不能把“发现了代码缺口”代替复现。

现在本地 grant 和触发对象共用 `remember/forget` 生命周期。锁只覆盖内存操作，不包含 SQL；清理按 grant ID 判断，旧回复不能删除同 execution 下的新 grant。普通完整窗口释放、过期 grant 的读回协调和失败拒绝都使用同一清理方法。拒绝的 COMMIT 回复丢失时重读控制表；能够证明旧 grant 已消失才清理，读回失败则保留上下文，重复调用可继续协调。没有删除 SQL 中的接受意图、Cron 水位、历史审计或 Journal。

这不改变 T/J、Split cursor、batchId、恢复预算或 CDC 原始 ACK 前缀协议。新增 SQL 控制记录不是旧 Journal/Snapshot 的替代形状，原持久化类名和字段保持兼容。

八项为正常拒绝、提交回复丢失、COMMIT 未发送、提交后读回不可用、旧拒绝、旧释放、完整窗口让出/重新取得触发、旧释放回复迟到。最后一项用门闩固定：旧释放已提交但未返回 → SQL 新 grant 为 held → 读回确认并清理旧本地状态 → 取得新 grant 和原触发 → 旧回复返回。断言新映射和触发仍存在，随后新 grant 正常拒绝回收。

## 本轮失败材料与复核规则

- 测试容器重启后本机映射从32814变成32815，首次七项在连接阶段全部失败。保留 runner 和异常，核对 Docker 实际映射及 SQL 就绪后才重跑；不是代码修复，也不算通过。
- 首轮后端全量为560/561：原 `WorkflowExecutionEngineSpec` 的 `close-1/open-2` 观察顺序失败。该测试的 `close` 在终止 Future 的异步观察回调中记录，与执行器的释放回调无先后保证；不把日志顺序本身说成物理资源仍未关闭。定向重跑通过，原失败日志保留；没有修改原测试或生产恢复协议。
- 第一轮真实矩阵的目标服务端窗口，在进程死后采到旧事务视图记录，但会话列表已空；杀进程前有精确 target GET_LOCK 会话及同线程事务。实验断言要求杀进程后仍同时观察到会话和事务，本次未满足，记 `evidence_incomplete`。保留前后观察，不能用这项声称那个服务端切点已验证；定向复核保持原断言，不放宽条件。

低干扰复核的最终退出码、批次/定向运行之别均写入汇总。不同 runner 的结果不拼成“同一批22/22”；出现未达到切点的原始失败也不会被后一次成功覆盖。后续只增加的延迟回复测试设施与较早冻结 runner 可能有测试源码差异，核验器分别保留完整清单，并要求所有现场运行的生产源码与最终生产源码一致。

本轮整批21/22；目标服务端窗口在无并行全量负载的定向复核中1/1通过。两份现场运行合计覆盖22种成功切点，选中样本共220行、1320个字段值，**不是一批22/22**。最后八项真实缓存验证8/8。实验结束确认客户端、InnoDB事务、临时账号均为0；本轮38个新schema和已有153个schema全部保留，本任务容器停止，没有删除数据卷。这里的低干扰复核不能用于推导生产发生概率或恢复时延。

## 未验证边界

仍仅支持可信 supervisor 管理的本机子 JVM、固定 MySQL 部署和静止 Source 的受管静态快照。不包含 supervisor 整个 JVM 重启后的重新收养、远端/Kubernetes fence、多 supervisor 竞争、数据库 failover、跨机器分区、多物理实例现场排空、恶意属性伪造、DDL、共享 CDC 和 CDC 多 owner 接管。

没有做70万张物理表、多 owner 长期压测或长期失败任务的堆/RSS 测量；缓存修复的行为验证不等于量化内存收益。Source/Sink 连接预算不包含 Journal、控制池、观察连接，页额度不是 RSS 硬限制。历史 SQL 意图、审计和证明保留，不代表已有历史保留期治理。永久阻塞 JDBC 仍会占用名额，结果未知时保持阻塞。

原 Split22项、CDC27项是[前一冻结源码的现场结果](../2026-10-23-snapshot-takeover/README.md)，本轮未把历史离线校验写成重新跑过，也不据此扩大为 CDC 自动接管保证。旧 C2 失败、所有先导实验和已有材料均保留。
