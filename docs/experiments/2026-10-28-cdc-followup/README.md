源码层面，待绑定取消现在通过 capture 命令锁和准入检查，提交未知时不能直接改写订阅状态；管理式关闭在 SDK task 启动未结束时保留关闭工作，调用方按超时返回 UNKNOWN。该工作使用有限工作线程；若 SDK 长期不结束，线程可能被占满。工厂返回后的停止检查只覆盖指定竞态，检查到真正启动之间和 SDK 的其他内部阶段仍需专门固定窗口验证。无观察器且源释放无法确认时保留 owner，不表示已有自动证明和释放机制。

本轮不证明 A05/A09 未绑定 marker 自动恢复、不证明所有 A/B 故障窗口、DDL、日志 GC、多 owner 或 guardian 自动接管、70 万真实源表、长期运行及 Flink 同负载对比。保留这些未验证边界，不能将单测或组件测试升级为端到端保证。

启动异常的额外探针在真实源连接关闭被测试代理模拟为结果未知时，保留服务端连接并查询状态库命名锁：修复前锁空闲，修复后锁被持有。修复前探针另有 JSON 数值类型转换错误；原始 `IS_FREE_LOCK` 查询仍明确记录为 1，不能把该次断言失败单独当成问题证明。修复后使用纠正的类型断言，查询结果为 0；测试 JVM 退出后实验库空闲。这是组件级测试，未覆盖跨进程自动接管。

完整 `sbt test` 本轮未完成：默认 1 GB 堆出现持续 GC、无最终结果，停止该次运行；3 GB 堆重试后仍无最终结果，观察到测试启动一千万条异步流并持续输出，约三分钟后停止以限制资源占用。尚未证明后台流是唯一阻塞原因；完整测试不能标记为通过。相关测试日志保留在实验压缩包中。
